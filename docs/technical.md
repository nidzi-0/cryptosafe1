# CryptoSafe Manager — техническое описание

## 1. Назначение документа

Данный документ описывает техническую архитектуру проекта **CryptoSafe Manager**, основные криптографические решения, структуру модулей, базу данных, механизмы безопасности и подход к тестированию.

CryptoSafe Manager — это локальный менеджер паролей, реализованный на Python. Приложение предназначено для безопасного хранения учётных данных пользователя в локальной зашифрованной базе данных.

---

## 2. Общая архитектура проекта

Проект построен по модульному принципу. Основная логика разделена на несколько уровней:

```text
src/
    core/
        crypto/
        vault/
        clipboard/
        audit/
        import_export/
        security/
    database/
    gui/
```

Высокоуровневая схема приложения:

```text
GUI → Core services → Database
```

### GUI-уровень

GUI-уровень отвечает за взаимодействие с пользователем:

* главное окно приложения;
* диалоги добавления и редактирования записей;
* настройки;
* просмотр журнала аудита;
* элементы управления clipboard, panic mode и auto-lock.

### Core-уровень

Core-уровень содержит основную бизнес-логику приложения:

* криптография;
* операции с хранилищем;
* генерация паролей;
* защищённый буфер обмена;
* аудит;
* импорт и экспорт;
* secure sharing;
* security hardening.

### Database-уровень

Database-уровень отвечает за работу с SQLite:

* создание таблиц;
* хранение зашифрованных записей;
* хранение параметров ключей;
* хранение журнала аудита;
* хранение служебной информации.

## 3. Основные модули

### `src/core/crypto`

Модуль отвечает за криптографические операции, связанные с мастер-паролем, ключами и совместимостью ранних спринтов.

Основные задачи:

* проверка мастер-пароля;
* получение ключевого материала;
* совместимость со старыми тестами;
* constant-time сравнение чувствительных значений.

### `src/core/vault`

Модуль отвечает за работу с записями хранилища.

Основные компоненты:

* `encryption_service.py` — шифрование и расшифрование данных;
* `entry_manager.py` — операции создания, чтения, изменения и удаления записей;
* `password_generator.py` — генерация и оценка стойкости паролей.

### `src/core/clipboard`

Модуль отвечает за безопасную работу с буфером обмена.

Функции:

* копирование пароля;
* копирование логина;
* автоматическая очистка;
* ручная очистка;
* предупреждения перед очисткой;
* platform adapter для разных ОС;
* ephemeral mode, если системный буфер недоступен.

### `src/core/audit`

Модуль отвечает за журналирование событий безопасности.

Функции:

* запись событий;
* экспорт журнала;
* подпись или HMAC-проверка;
* hash-chain защита;
* проверка целостности;
* ротация логов.

### `src/core/import_export`

Модуль отвечает за импорт, экспорт и безопасный обмен данными.

Поддерживаемые возможности:

* encrypted JSON;
* CSV;
* Bitwarden import;
* LastPass import;
* secure sharing;
* QR/key exchange;
* проверка целостности;
* защита от повреждённых и вредоносных файлов.

### `src/core/security`

Модуль отвечает за security hardening, реализованный в Sprint 7.

Функции:

* защита от timing side-channel атак;
* secure memory management;
* auto-lock;
* panic mode;
* tray/background service;
* session recovery;
* screen-lock detection;
* platform security policy;
* UX и validation helpers.

## 4. Криптографическая архитектура

### 4.1. Мастер-пароль

Мастер-пароль используется для разблокировки хранилища и получения криптографического материала.

Мастер-пароль:

* не хранится в открытом виде;
* проверяется через криптографический hash/KDF;
* используется только для получения ключей;
* требуется повторно после auto-lock или panic mode.

---

## 5. Argon2

Для проверки мастер-пароля используется Argon2id.

Назначение Argon2:

* защита от перебора паролей;
* повышение стоимости brute-force атак;
* использование memory-hard механизма;
* безопасная проверка мастер-пароля без хранения его в открытом виде.

Argon2id выбран потому, что он устойчивее к GPU/ASIC-перебору, чем простые hash-функции.

---

## 6. PBKDF2-HMAC-SHA256

PBKDF2-HMAC-SHA256 используется там, где требуется получение ключевого материала по требованиям проекта.

Назначение PBKDF2:

* получение ключей из пароля;
* использование соли;
* многократные итерации;
* совместимость с распространёнными криптографическими практиками.

---

## 7. AES-256-GCM

Для шифрования записей используется AES-256-GCM.

AES-GCM обеспечивает:

* конфиденциальность данных;
* проверку целостности;
* аутентификацию ciphertext;
* обнаружение изменения зашифрованных данных.

Каждая операция шифрования использует уникальный nonce.

Типовая схема:

```text
plaintext + key + nonce → AES-GCM → ciphertext + authentication tag
```

При расшифровании authentication tag проверяется автоматически. Если данные были изменены, операция расшифрования завершается ошибкой.

---

## 8. Разделение ключей

В проекте используется принцип key separation.

Разделяются:

* ключи аутентификации;
* ключи шифрования хранилища;
* ключи экспорта;
* ключи sharing;
* ключи audit-подписей.

Это снижает риск повторного использования одного ключа в разных целях.

---

## 9. Структура записи хранилища

Запись хранилища может содержать:

* идентификатор;
* название;
* имя пользователя;
* пароль;
* URL;
* заметки;
* категорию;
* теги;
* дату создания;
* дату изменения;
* признак удаления.

Чувствительные поля перед сохранением шифруются.

Пример логической структуры:

```text
VaultEntry
    id
    title
    username
    encrypted_password
    url
    notes
    tags
    created_at
    updated_at
```

## 10. База данных

В качестве локального хранилища используется SQLite.

База данных может содержать таблицы:

* `vault_entries` — записи хранилища;
* `key_store` — служебные данные ключей;
* `audit_log` — журнал аудита;
* `settings` — настройки приложения;
* `shared_entries` — данные secure sharing;
* `import_export_history` — история импорта и экспорта;
* `contacts` — контакты для обмена ключами.

Данные паролей не должны храниться в открытом виде.

## 11. Vault operations

Основные операции с хранилищем:

### Добавление записи

1. Пользователь вводит данные.
2. Данные валидируются.
3. Чувствительные поля шифруются.
4. Запись сохраняется в SQLite.
5. Событие фиксируется в журнале аудита.

### Редактирование записи

1. Запись выбирается пользователем.
2. Данные расшифровываются для отображения.
3. Пользователь вносит изменения.
4. Обновлённые данные снова шифруются.
5. Запись сохраняется.

### Удаление записи

Удаление может быть мягким, то есть запись помечается как удалённая. Это снижает риск случайной потери данных.

### Поиск

Поиск выполняется по названию, URL, имени пользователя, заметкам и тегам. Для security hardening добавлены вспомогательные constant-time операции.

Поддерживаются:

## 13. Защищённый буфер обмена

Буфер обмена является чувствительным местом, потому что скопированный пароль может быть прочитан другими приложениями.

В проекте реализовано:

* копирование только при разблокированном хранилище;
* автоматическая очистка;
* ручная очистка;
* предупреждение перед очисткой;
* ephemeral mode;
* platform adapter;
* panic mode clipboard clearing.

Если системный clipboard недоступен, используется внутренний защищённый режим.

## 16. Secure sharing и QR/key exchange

Механизм secure sharing позволяет передавать отдельные записи без раскрытия всего хранилища.

Поддерживаются:

* password-based sharing;

QR/key exchange используется для обмена ключевой информацией и передачи защищённых данных.

## 17. Security hardening

Sprint 7 добавляет дополнительные механизмы защиты.

### Side-channel protection

Реализованы:

* constant-time сравнение байтов;
* constant-time сравнение строк;
* поиск без раннего выхода;
* timing noise;
* статистические timing-тесты.

### Secure memory management

Реализованы:

* `SecretHolder`;
* `SecureMemory`;
* `SecureHeapAllocator`;
* `SecureHeapBlock`;
* `StackSecret`;
* `VolatileSecret`;
* попытка `VirtualLock/mlock`;
* очистка памяти через `ctypes.memset`;
* canary values;
* guard-зоны.

Полный контроль над памятью в Python невозможен, поэтому часть механизмов реализована как программное приближение.

### Auto-lock

Auto-lock отслеживает:

* активность мыши;
* ввод с клавиатуры;
* фокус окна;
* screen lock events.

После неактивности хранилище блокируется.

### Panic mode

Panic mode выполняет:

* блокировку хранилища;
* очистку clipboard;
* очистку чувствительных данных;
* закрытие окон;
* запись события в audit log;
* восстановление только после проверки мастер-пароля.

### Session recovery

Session recovery сохраняет только UI/session metadata:

* выбранные записи;
* поисковый запрос;
* положение окна;
* профиль безопасности.

Чувствительные данные и пароли в session snapshot не сохраняются.

## 22. Ограничения

Известные технические ограничения:

* Python не позволяет полностью контролировать все копии объектов в памяти;
* настоящая очистка stack frames невозможна на уровне Python;
* hardware-level защита зависит от среды выполнения;
* system tray может отличаться на разных ОС;
* Windows Hello, Keychain и Linux keyring требуют дополнительной системной интеграции.

---

## 23. Итог

CryptoSafe Manager представляет собой локальный менеджер паролей с модульной архитектурой, шифрованием AES-256-GCM, Argon2/PBKDF2, SQLite-хранилищем, защищённым буфером обмена, аудитом, импортом/экспортом, panic mode и дополнительным security hardening.

Проект объединяет компоненты всех спринтов в единую систему и может быть запущен из исходного кода или собран в исполняемый файл.
